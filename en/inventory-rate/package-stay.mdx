## Package list

Basic information and Rate plan for your overnight packages, in one place. Packages can be reordered freely.

### Basic information

<Frame>
  ![Pkg List](/images/en-pkg-list.png)
</Frame>

Every overnight package built on a room type, with its name, inventory, and timetable at a glance.

### Rate plan

<Frame>
  ![Pkg List Rate](/images/en-pkg-list-rate.png)
</Frame>

Check and set a package's base rate and its rate periods.

- **Base rate**: the selling rate applied on any date without a period of its own.
- **Rate periods**: add a period and the package sells at a different rate for those dates only.

Two things make the Rate plan screen easier to work in.

- **Expand or collapse all**: "Expand all | Collapse all" at the top of the list opens or closes the rate plan for every package at once. With many packages, you get to the one you want quickly.
- **Multi-select room type filter**: the room type chips at the top take more than one selection, so you can pull up just the types you want and compare them side by side.

<Note>
  **Changes apply temporarily first. Nothing is final until you press "Save"**

  Everything you do on the Rate plan tab (bulk apply, Import, Add period, Align order, editing rows) lands on screen first as a temporary change.

  - A changed package card carries a "Temporary change" badge, and the changed cells and order are highlighted.
  - The Undo (↩︎) button on a card reverts only that package's changes to their pre-save state.
  - Press "Save" in the top bar to commit. Leave the page without saving and the changes are gone.
</Note>

## Create package

<Frame>
  ![Create Pkg](/images/en-create-pkg.png)
</Frame>

Pick a room type, fill in the name, currency, timetable, and the rest, and the overnight package exists.

Here is what you enter:

- **Room type (required)**: the room type for this package. Inventory follows the number of rooms in that type, and the room type cannot be changed after creation.
- **Package name (required)**: the name that distinguishes this package.
- **Currency**: the currency the package rate is in. Like the room type, it cannot be changed after creation.
- **Timetable**: the package's check-in and check-out times.
- **Inventory settings**
  - **Max inventory**: caps how many can be sold, up to the number of rooms in the room type.
  - **Auto top-up**: tops the availability of every mapped channel package back up so inventory stays level. If the number you set matches actual inventory, it draws down as sales come in.
  - **Units per booking**: how many rooms one booking consumes. Set it to 2 and each booking draws 2 from inventory. Inventory stays accurate even when several rooms are sold as a single package, as with capsule rooms.

<Warning>
  Change the units per booking and it applies to rate adjustments made from then on. Adjustments already in place are untouched.
</Warning>

<Accordion title="Spotting a booking with units per booking applied">
  When a booking comes in for a package that sets units per booking, that setting shows up in Bookings.

  <Frame>
    ![Booking Scale Factor](/images/booking_scaleFactor.png)
  </Frame>

  - **Package**: a "booking ×2" badge next to the package name shows the units per booking currently set.
  - **Quantity**: "booking ×2 applied" shows the units per booking that was in force when the booking synced.
</Accordion>

### **Setting the package rate**

<Frame>
  ![Create Pkg Rate](/images/en-create-pkg-rate.png)
</Frame>

Turn on the Rate setting and you control this package's rate directly.

<Frame>
  ![Create Pkg Rate Select](/images/en-create-pkg-rate-select.png)
</Frame>

Pick the rate to apply. If the one you need does not exist, press `+ Create rate` and make it on the spot. The [rates guide](/en/inventory-rate/rate) covers this in full.

### Package inclusions

<Frame>
  ![Create Pkg Inclusions](/images/create-pkg-inclusions.png)
</Frame>

Pick the inclusions that apply to this package alone. Their total, summed by inclusion quantity, becomes the package's base rate. If the inclusion you need does not exist, press `+ Create inclusion`. The [inclusions guide](/en/inventory-rate/inclusion) covers this in full.

### Extra rate adjustment

<Frame>
  ![Create package, rate scale factor](/images/en-create-pkg-rate-scale.png)
</Frame>

Add a markup or a discount on top of the package's base rate. The final rate, calculated from the amount or percent you enter, is shown immediately.

### Rate range

<Frame>
  ![Create Pkg Min Max](/images/en-create-pkg-rate-range.png)
</Frame>

Set a minimum and maximum for the selling rate. Set both, or just one. The maximum has to be higher than the minimum.

### Occupancy-based pricing

<Frame>
  ![Create Pkg Obp](/images/en-create-pkg-obp.png)
</Frame>

On channels that support occupancy-based pricing (Agoda, for one), a per-person surcharge is added to the room rate once guests exceed base occupancy. Channels without that support price against max occupancy.

## Setting rate periods

When you want a different rate in peak season than in the quiet months, rate periods give you the room to do it.

### Rate periods

Add a period and a different rate applies for those dates only. The [periods guide](/en/inventory-rate/period) covers how to build one.

<Frame>
  ![Create Pkg Rate Period](/images/en-pkg-rate-periods.png)
</Frame>

### Adding a period

Link a period you built on the periods page to a package, and it has rate periods.

- **Add to several packages at once**: if a period is linked to no package at all, an "Add N unlinked periods" link appears at the top of the list. An unlinked period sells at the base rate for those dates, so follow the link when you see it.
  <Frame>
    ![Add multiple periods](/images/en-pkg-add-unlinked-periods.png "Add multiple periods")
  </Frame>

- **Add to a single package**: use the "Add period" button on the package card. The adjustment stored on the period comes across as the starting value.
  <Frame>
    ![Add a period to one package](/images/en-pkg-add-period.png "Add a period to one package")
  </Frame>
- An added period slots in at its priority position from the periods page.

<Warning>
  If a period you add overlaps one already there, the higher period wins and the rate can change. Check each package's rate before you save.
</Warning>

### Applying rate periods to other packages

Rate periods set on one package can be carried over to others, so you are not repeating the same periods package by package.

<Frame>
  ![Bulk update rate plan modal](/images/en-pkg-bulk-rate-plan-modal.png "Bulk update rate plan modal")
</Frame>

- **Bulk apply**: from the option (⋮) menu at the top of the list, pick one package to copy from and apply it to many at once.
  <Frame>
    ![Bulk update rate plan button](/images/en-pkg-bulk-rate-plan-button.png "Bulk update rate plan button")
  </Frame>
- **Import**: the "Import" button on a package card pulls another package's rate periods into this one.
  <Frame>
    ![Import rate plan into one package](/images/en-pkg-import-rate-plan.png "Import rate plan into one package")
  </Frame>

<Info>
  **What copies is the period structure and the adjustments, not the amounts**

  - The final rate is recalculated by applying the adjustments to each package's own rate. A package's base rate never moves.
  - Periods that exist only on the receiving package are kept, and rates you changed individually are kept too.
  - A calculated rate that falls outside the package's minimum or maximum is pulled back inside the range.
  - Packages on a fixed rate, packages with no rate set, and packages in a different currency are excluded, and the list says why.
</Info>

### Align period order

When periods overlap, the one higher up applies first. Out of order, they can sell at a rate you did not intend, so a package's rate periods can be aligned to match the priority on the periods page.

- **Every package**: run "Align period order" from the option (⋮) menu. Packages already in the right order are skipped.
- **One package**: use the "Align order" button on the package card.

<Check>
  Only the order changes. No period is added or removed, and no rate or adjustment is touched.
</Check>
