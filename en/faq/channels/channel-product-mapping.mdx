title: "How do I map channel packages?"
description: "How to map channel packages to VCMS packages, and how to fix things when a mapping is wrong or room setups differ by channel."
---

## If channel package mapping is wrong, will inventory be off?

> Yes. If a channel package is not mapped to a VCMS package, or is mapped to a different room type, bookings come in but the right inventory is not deducted.

<Info>
  VCMS inventory runs in this order: room type, package, channel package. When a booking comes in through an unmapped channel package, VCMS cannot tell which room type it belongs to, so inventory is not deducted. If another channel sells the same room in the meantime, you get an overbooking. When you create a new promotional package or rate plan on a channel, a new channel package appears, and it is not mapped automatically.
</Info>

1. In Settings > Channel list, check for any channel marked `Unmapped channel packages`.
2. In Settings > Channels > Connected channels > Channel packages, choose the VCMS package of the right room type for each unmapped channel package, map it, and save.
   Do not map Yanolja hard block packages. Leave them unmapped.
3. If a package you just created on a channel is not in the list, go to Settings > Channels > Connected channels, choose the channel, and click `Sync channel packages` in Property info.
4. In Distribution, if Availability differs from the number of rooms actually left, correct it and click `Save`.

<Note>
  If you also use VCLOUD, bookings from unmapped channel packages are created under an unassigned room type.
</Note>

If this does not solve the problem, click the Support button and report it.

## How do I set inventory and rates?

> You set inventory and rates on the VCMS package. When you map a channel package to the VCMS package, those values sync to the channel.

1. Create packages in VCMS based on room types.
   Create packages first, based on the room types and rates your accommodation uses.
2. Map channel packages to VCMS packages.
   A mapped channel package gets the same rate as the VCMS package and shares its inventory.

<Info>
  If you use the VENDIT VCLOUD service, channel packages that are not mapped to a package are created under an unassigned room type.
</Info>

<Accordion title="Can I hide or delete packages I don't sell?">
  You can hide them, but deleting is not supported. Deleting an unmapped channel package could also remove the booking data tied to it. To keep data consistent, VCMS offers hiding instead of deleting.

  1. In Settings > Channels > Connected channels > Channel packages, click 'Unmapped channel packages view settings'.
  2. Click the Hide/Show button and save to hide the channel packages you want.

  Hiding applies only to the VCMS screen. Do not hide a package you are selling on a channel. Map it to a VCMS package instead. A hidden channel package that is still on sale on the channel can still get bookings, which can cause an overbooking.
</Accordion>

<Accordion title="Can I sell only certain channel packages at a markup or discount?">
  Yes. Set the Final channel rate on a channel package to mark up or discount only that channel package. In Settings > Channels > Connected channels > Channel packages, choose the channel package to mark up or discount and set its Final channel rate. The change then applies.
</Accordion>

## How do I fix a channel package that is mapped incorrectly?

> On the Channel packages screen, unmap it and map it again to the right VCMS package. You can change the mapping at any time.

<Info>
  If a channel package is mapped to a package of a different room type, bookings from that channel reduce the wrong type's inventory, and the type actually sold stays on sale. Left as is, this can lead to overbooking.
</Info>

1. In Bookings, open the booking that deducted inventory incorrectly and check the sales channel package name.
2. In Settings > Channels > Connected channels > Channel packages, click that channel package.
3. Click `Unmap channel package`, choose the right VCMS package, map it again, and save.
   Inventory and rates are not adjusted on a package you have unmapped. Do not leave it unmapped. Map it again right away.
4. In Distribution, check that Availability for the related room type matches the number of rooms actually left. If it differs, correct it and save.

If this does not solve the problem, click the Support button and report it.

## How do I map when room setups differ by channel?

> If you have a mix of channels that sell by room number and channels that sell by type, align your VCMS room types and package structure first, then map.

<Info>
  VCMS sets inventory from a room type's Number of rooms. If you map type-based channel packages (for example, 5 Standard rooms) and room-based channel packages (for example, Room 301) to the same package, VCMS cannot tell which room sold, so inventory counts can seem wrong. Once the structure is aligned, the counts match.
</Info>

<Accordion title="Method 1. Split room types by room number">
  Use this when rooms differ in setup and cannot be assigned in place of each other. In Settings > Room types, create a room type for each room (for example, Room 301 type, Room 302 type) and create a package for each type. Then map the room packages from all channels one by one.
</Accordion>

<Accordion title="Method 2. Create separate packages per room">
  Use this when it is fine to swap rooms when assigning them. In Settings > Packages, create a package for each room and set `Max inventory` to 1 in Inventory settings. Map room-based channel packages to the room packages, and type-based channel packages to the type packages.
</Accordion>

After that, in Settings > Channels > Connected channels > Channel packages, check that every channel package is mapped to fit the new structure, then save.

<Warning>
  - If you delete a room type, its mapped packages are deleted too. Map the channel packages that were mapped to those packages again.
  - Moving a room to a different type changes inventory counts. If you are syncing inventory, check the dates you are selling before you move it.
  - If you also use VCLOUD, make the room types and Number of rooms identical in VCLOUD and VCMS. They do not match automatically.
</Warning>
