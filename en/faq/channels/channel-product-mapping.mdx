title: "How do I map channel packages?"
description: "How to map channel packages to VCMS packages, and how to fix a wrong mapping or align room setups that differ by channel."
---

## Does inventory go wrong if channel packages are mapped incorrectly?

> Yes. If a channel package isn't mapped to a VCMS package, or is mapped to a different room type, the correct inventory isn't deducted when a booking comes in.

<Info>
  VCMS inventory runs in this order: room type, package, channel package. When a booking comes in through an unmapped channel package, VCMS can't tell which room type it belongs to, so inventory isn't deducted. If the same room sells on another channel in the meantime, an overbooking occurs. When you create a new promotion package or rate plan on a channel, a new channel package appears, but it isn't mapped automatically.
</Info>

1. In Settings > Channel list, check whether any channel shows the `Unmapped channel packages` label.
2. In Settings > Channel > Connected channels > Channel packages, choose the VCMS package of the correct room type for each unmapped channel package, map it, and save.
   Don't map Yanolja hard block packages. Leave them unmapped.
3. If a package you newly created on the channel isn't in the list, go to Settings > Channel > Connected channels, choose the channel, and click `Sync channel packages` in Property info.
4. In Distribution, if Availability differs from the actual number of rooms left, correct it and click `Save`.

<Note>
  If you also use VCLOUD, bookings from unmapped channel packages are created under an unassigned room type.
</Note>

If that doesn't fix it, click the Support button and report it.

## How do I set inventory and rates?

> You set inventory and rates on the VCMS package. When you map a channel package to the VCMS package, those values sync to the channel.

1. In VCMS, create packages based on room types.
   Create packages first, based on the room types and rates in use at your accommodation.
2. Map channel packages to VCMS packages.
   A mapped channel package gets the same rate as the VCMS package and shares its inventory.

<Info>
  If you use the VENDIT VCLOUD service, channel packages that aren't mapped to a package are created under an unassigned room type.
</Info>

<Accordion title="Can I hide or delete packages I don't sell?">
  You can hide them, but deleting isn't supported. Deleting an unmapped channel package could also remove the booking data tied to it, so to keep data consistent, VCMS offers hiding instead of deleting.

  1. In Settings > Channel > Connected channels > Channel packages, click 'Unmapped package visibility'.
  2. Click the Hide/Show button and save to hide the channel packages you want.

  Hiding applies only to VCMS screens. Don't hide packages being sold on a channel. Map them to VCMS packages instead. A hidden channel package that is still being sold on the channel can receive bookings and cause an overbooking.
</Accordion>

<Accordion title="Can I sell only certain channel packages at a surcharge or discount?">
  Yes. Set the Final channel rate of a channel package to sell only that channel package at a surcharge or discount. In Settings > Channel > Connected channels > Channel packages, choose the channel package and set its Final channel rate to apply it.
</Accordion>

## How do I fix an incorrectly mapped channel package?

> On the Channel packages screen, unmap the channel package and map it again to the correct VCMS package. You can change a mapping at any time.

<Info>
  If a channel package is mapped to a package of a different room type, bookings from that channel reduce the wrong type's inventory, while the type that actually sold keeps selling. If you leave it, this can lead to an overbooking.
</Info>

1. In Bookings, open the booking that deducted inventory incorrectly and check the name of the channel package it sold through.
2. In Settings > Channel > Connected channels > Channel packages, click that channel package.
3. Click `Unmap channel package`, choose the correct VCMS package, map it again, and save.
   Inventory and rates aren't adjusted for an unmapped package. Don't leave it unmapped. Map it again right away.
4. In Distribution, check that Availability for the affected room type matches the actual number of rooms left. If it doesn't, correct it and save.

If that doesn't fix it, click the Support button and report it.

## How do I map packages when room setups differ by channel?

> If you have a mix of channels that sell by room number and channels that sell by type, align your VCMS room types and package structure first, then map.

<Info>
  VCMS sets inventory from a room type's Number of rooms. If you map type-based channel packages (for example, Standard, 5 rooms) and room-based channel packages (for example, Room 301) to the same package, VCMS can't tell which room sold, and the inventory count may seem wrong. Aligning the structure fixes this.
</Info>

<Accordion title="Method 1. Split room types by individual room">
  Use this when rooms differ in setup and can't be assigned in place of one another. In Settings > Room types, create a room type for each room (for example, Room 301 type, Room 302 type) and create a package for each type. Then map the room packages of all channels one by one.
</Accordion>

<Accordion title="Method 2. Create separate packages for each room">
  Use this when it's fine to swap room assignments. In Settings > Packages, create a package for each room and set `Max inventory` to 1 in Inventory settings. Map room-based channel packages to the room packages, and type-based channel packages to the type packages.
</Accordion>

After you reorganize, go to Settings > Channel > Connected channels > Channel packages, check that every channel package is mapped to match the new structure, and save.

<Warning>
  - When you delete a room type, its mapped packages are deleted too. Map the channel packages that were mapped to those packages again.
  - When you move a room to another type, the inventory count changes. If inventory sync is on, check the dates that are Open sell before you move the room.
  - If you also use VCLOUD, make the room types and Number of rooms the same in VCLOUD and VCMS. They don't match automatically.
</Warning>
